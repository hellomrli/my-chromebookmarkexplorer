# 编辑和恢复收藏夹

[返回文档入口](index.md)

## 选择正确的文件

自动检测会寻找 Chrome 用户目录中的 `Default`、`Profile 1` 等 Profile。未发现 Profile 时，用“打开文件”选择已有的 `Bookmarks` 或兼容 JSON 文件。

左侧选择当前文件夹；勾选左侧文件夹或右侧书签以执行批量删除、移动。右键菜单可全选或取消勾选。重命名是单项操作；Chrome 根收藏夹不能重命名。

“批量编辑”对选中书签的网址执行查找替换，可使用普通文本或正则表达式；先核对选择范围和表达式。标签存储在书签数据中，不应假定 Chrome 会提供相同的标签界面。

## 导入和导出

| 格式 | 导出 | 导入 |
|---|---|---|
| HTML | 支持 Netscape 书签形式 | 按钮存在，当前实现会报告尚未完成 |
| JSON | 支持，包含 `roots` | 支持，须为包含 `roots` 的书签结构 |
| CSV | 支持名称、网址、路径和添加时间 | 不支持 |

导入前在左侧选择目标文件夹。JSON 各根节点的子项会加入当前文件夹，导入后检查层级与数量并保存。仅改变文件扩展名不能完成格式转换。

## 保存并恢复

保存时检查 Chrome 进程；检测到仍在运行就会拒绝写入。关闭 Chrome，包括后台进程，再重试。

目标文件已存在时，程序尝试在同目录复制 `Bookmarks.backup-YYYYMMDD-HHMMSS`。备份复制结果没有独立的成功校验，因此重要数据先自行备份。正式写入使用 Qt 的 `QSaveFile`，并移除旧 `checksum`，供 Chrome 重建。

恢复步骤：

1. 关闭 Chrome 和本工具。
2. 保留当前文件，再选一份确认完整的备份复制回原来的 `Bookmarks` 路径。
3. 打开 Chrome 检查书签数量及层级。

使用“另存为”保存副本可以避免直接覆盖源文件；切换文件或退出时留意未保存提示。
